# Frustum

**한밤의 캠핑장, 손전등 술래잡기.** 후드를 쓴 아이들이 달빛 아래 캠핑장에서 손전등으로 서로를 찾는다.
손전등이 비추는 곳만 따뜻하게 밝고, 그 밖은 어둠이다. 보이는 것은 내(그리고 팀원의) 시야뿐이고,
시야 밖의 상대는 **서버가 아예 보내지 않는다.**

- 클라이언트: Three.js(WebGL2) — 모바일 브라우저에서 바로 실행, PWA 매니페스트 포함
- 서버: Node.js + `ws` — 권위 서버(30Hz 시뮬레이션, 15Hz 스냅샷)
- 빌드 단계 없음

## 실행

```bash
npm install
npm start          # http://localhost:3000  (PORT 환경변수로 변경)
npm test
```

같은 네트워크의 휴대폰에서 `http://<PC IP>:3000` 으로 접속하면 된다. 혼자 접속해도 봇이 채워진다.

메뉴에는 두 가지 시작 방법이 있다.

- **혼자 하기 (봇전)**: 서버 없이 브라우저 안에서 서버 로직(`server/game.js`)을 직접 실행한다. 정적 호스팅(GitHub Pages)만으로 동작한다.
- **온라인 접속**: WebSocket 서버에 접속한다. 같은 호스트의 `/ws`가 기본이고, `?server=wss://호스트` 로 다른 서버를 지정할 수 있다.

## 설정

메뉴의 설정 버튼이나 게임 중 ⚙️ 버튼으로 연다. 기기에 저장된다.

- 조이스틱 고정(항상 같은 자리에 표시), 왼손 모드(조이스틱과 버튼 좌우 반전)
- 회전 감도, 효과음 크기, 진동, 성능 정보 표시
- 게임 중에는 "게임 나가기"로 메뉴로 돌아간다

## Render 배포 (멀티플레이 서버)

`render.yaml`(Blueprint)이 들어 있다. render.com 가입 → **New → Blueprint** → 이 저장소 선택 → Apply.
몇 분 뒤 `https://frustum-xxxx.onrender.com` 같은 주소가 생기고, 그 주소를 열면 서버가 직접 서빙하는 게임에서 "온라인 접속"이 바로 된다.
GitHub Pages에서도 온라인 접속을 쓰려면 `client/settings.js`의 `DEFAULT_SERVER`에 그 주소를 넣는다.
무료 플랜은 15분간 접속이 없으면 잠들고, 다시 깨어나는 데 최대 1분 걸린다(클라이언트가 자동으로 재시도한다).

## GitHub Pages 배포

`main`에 푸시하면 `.github/workflows/pages.yml`이 테스트 후 `npm run build:pages`로 `dist/`를 만들어 배포한다.
저장소 **Settings → Pages → Source를 "GitHub Actions"** 로 한 번만 바꿔 두면 된다.
주소는 `https://<사용자>.github.io/Frustum/` 이다. Pages에는 서버가 없으므로 이 주소에서는 "혼자 하기"만 된다.
멀티플레이는 `npm start` 서버를 Render 등에 올리고 `https://<사용자>.github.io/Frustum/?server=<서버 호스트>` 로 접속한다.

| | 이동 | 회전 | 손전등 | 구르기 | 조명탄 |
|---|---|---|---|---|---|
| 모바일 | 왼쪽 드래그(조이스틱) | 오른쪽 드래그 | 손전등 버튼 | 구르기 버튼 | 조명탄 버튼 |
| PC | WASD | 마우스 드래그 / ←→ / Q·E | Space | Shift | F |

## 게임 규칙

한 방에 8명(모자라면 봇)이 들어간다. 메뉴에서 규칙 3가지 × 인원 구성 2가지를 고른다(서버는 조합마다 방 하나).

| 규칙 | 부활 | 승리 조건 |
|---|---|---|
| 데스매치 | 3초 후 부활 | 3분 동안 킬이 가장 많은 사람/팀 |
| 점수제 데스매치 | 3초 후 부활 | 목표 킬(개인전 10, 팀전 15)을 먼저 달성. 5분이 지나면 킬 1위 |
| 서바이벌 | 없음 | 마지막 생존자/팀. 2분이 지나면 생존자 수 → 킬 수 |

- **개인전**: 8명 각자 싸운다. 시야 공유 없음.
- **2인 팀전**: 2명씩 4팀. 팀원과 시야를 공유한다.
- **독구름**(서바이벌 전용): 시작 15초 뒤부터 맵 가장자리에서 안쪽으로 조여 와 100초에 중앙 14m × 14m만 남는다. 구름 속에 3초 머물면 탈락하고, 밖으로 나오면 천천히 회복한다. 구름은 시야와 무관하게 항상 보인다.
- 동률이면 무승부. 라운드가 끝나면 6초 후 다음 라운드. 시작 후 3초 동안은 공격할 수 없다.
- 라운드 도중에 들어온 사람은 봇의 자리를 이어받는다.
- **손전등 빔**: 6m, 40° 원뿔 안에서 벽에 가리지 않은 적을 처치한다. 쿨다운 4초.
- **구르기**: 이동 방향(가만히 있으면 앞)으로 0.3초 동안 약 4.5m 이동, 그동안 무적. 구르는 중에는 공격 불가. 쿨다운 3초.
- **조명탄**: 앞으로 최대 8m 던져 4초 동안 반경 7m를 팀 시야로 밝힌다(벽 그림자 적용). 우리 팀에게만 보인다. 쿨다운 12초.
- 스킬 버튼에는 남은 쿨다운이 숫자로 표시된다.
- **맵**(라운드마다 순서대로 바뀜):
  - 한밤의 캠핑장: 중앙 오두막, 텐트, 울타리와 돌담
  - 소나무 숲: 나무가 빽빽해 시야가 자주 끊기는 좁은 오솔길
  - 호숫가: 가운데 십자 모양 호수. 물은 걸어서 건널 수 없지만 시야는 막지 않아 건너편이 보인다(손전등은 닿지 않는다)
- **아이템**: 라운드 시작 때 3개, 이후 7초마다 하나씩(최대 6개) 생긴다. 시야 안에 있을 때만 보이고, 밟으면 줍는다.
  - 🔋 배터리: 손전등과 조명탄 쿨다운 즉시 충전
  - 👟 운동화: 6초 동안 40% 빨라짐
  - 🛡️ 반사 조끼: 손전등 빛을 한 번 막아 줌(20초)
  - 👻 그림자 망토: 6초 동안 상대에게 보이지 않음. 2.2m 안까지 다가오면 보이고, 공격하면 벗겨진다.
    서버가 위치 자체를 보내지 않으므로 핵으로도 볼 수 없다.
- **사운드**: 오디오 파일 없이 Web Audio로 합성. 시야 안의 빔/구르기는 위치에 따라 좌우로 들린다.
  적이 시야에 들어오면 경고음이 난다. 우측 상단 🔊 버튼으로 끈다.

## 구조

```
shared/   서버·클라이언트 공용 (같은 코드로 판정과 화면을 일치시킨다)
  config.js   FOV, 시야 거리, 속도 등 상수
  map.js      맵과 벽(AABB)
  vision.js   시야 판정(canSee), 시야 다각형(computeVisionFan)
  sim.js      이동/충돌 시뮬레이션
server/
  game.js     게임 로직, 팀별 시야 계산, 플레이어별 스냅샷
  bots.js     봇 (자기 시야에 들어온 적만 인지)
  nav.js      봇 길찾기 (1m 격자 A*)
  index.js    HTTP 정적 서버 + WebSocket
client/
  main.js     렌더링, 예측/보간, 컬링, HUD
  fog.js      시야 마스크(Fog of War)
  input.js    터치/키보드 입력
  world.js    캠핑장 맵 꾸미기(울타리, 생울타리, 돌담, 나무, 텐트, 오두막)와 바닥 텍스처
  character.js 캐릭터 모델, 절차적 애니메이션, 처치 이펙트
  prefs.js    사용자 설정 저장
  minimap.js  미니맵 (서버가 보내준 정보만 그린다)
  audio.js    효과음 합성
  settings.js Pages에서 쓸 기본 서버 주소
```

## 요구사항별 구현

### 1. 시야각 기반 마스킹 — `client/fog.js`
- 캐릭터의 시야 = 수평 FOV 90° · 거리 20m 부채꼴에서 벽 뒤 그림자를 뺀 다각형 (+ 몸 주변 1.6m).
- 매 프레임 이 다각형을 맵 전체를 덮는 512² 텍스처에 그리고, 모든 월드 머티리얼이 자기 월드 좌표로
  그 텍스처를 샘플링한다. 시야 밖은 벽·캐릭터 0%, 바닥 격자만 5% 밝기로 남는다.
- 화면 전체 후처리 패스가 없어서 모바일 GPU 부담이 작다.
- 팀전에서는 살아있는 팀원의 시야 다각형을 MAX 블렌딩으로 합쳐 시야를 공유한다.

### 2. 시야 기반 동기화 — `server/game.js`
- 서버가 팀별로 "보이는 적" 집합을 계산하고(`computeVisibility`), 플레이어마다 그 집합에 속한 적만
  스냅샷에 담는다(`snapshotFor`). 시야 밖 적의 좌표는 클라이언트 메모리에 존재하지 않으므로
  월핵/맵핵으로 읽어낼 것이 없다.
- 스냅샷에서 빠진 플레이어는 클라이언트가 즉시 삭제한다. 로스터와 킬 피드에는 위치가 없다.
- 이동은 서버 권위: 입력값 클램프, 틱당 입력 1개 예산(스피드핵 방지), 회전 속도 제한(순간 360° 스캔 방지),
  초당 메시지 수와 페이로드 크기 제한.
- 클라이언트는 같은 `sim.js`로 자기 이동을 예측·보정하고, 다른 플레이어는 110ms 보간한다.

### 3. 프러스텀 컬링 — `client/main.js`
- 벽은 `InstancedMesh` 1개(드로우콜 1회). 매 프레임 **시야 광선이 닿은 벽 ∩ 카메라 절두체 안의 벽**만
  인스턴스 버퍼에 채운다. 보통 41개 중 6~12개만 그려진다.
- 플레이어는 서버가 보낸 것만 존재하고, 그중 카메라 절두체 밖은 `visible = false`.
- 좌상단 HUD에 fps / 드로우콜 / 그려진 벽·플레이어 수가 표시된다.

### 4. 모바일
- 터치 조이스틱 + 드래그 회전 + 공격 버튼, 가로/세로 화면 모두 지원, 노치 safe-area 대응.
- 픽셀 비율 최대 2로 제한, 프레임이 떨어지면 렌더 해상도를 자동으로 낮추고 여유가 생기면 복구.
- 그림자 맵·안티앨리어싱·후처리 없음, 지오메트리와 머티리얼 공유.
- 스토어 배포가 필요하면 `client/`를 Capacitor 같은 웹뷰 래퍼로 감싸면 된다.

## 설정

`shared/config.js`에서 조정한다. 서버는 모드별로 방을 하나씩 운영한다.

## 알아둘 점

- 맵이 평지 + 수직 벽이라 시야 판정은 XZ 평면에서 한다(절두체의 위/아래 평면은 아무것도 자르지 않음).
  높낮이가 있는 맵으로 확장하려면 `vision.js`에 수직 판정을 추가해야 한다.
- 시야 경계에서 적이 갑자기 튀어나오지 않도록 서버가 0.3m 여유(`VIS_MARGIN`)를 두고 보낸다.
- 혼자 하기 모드는 서버 로직이 클라이언트에서 돌기 때문에 서버 쪽 시야 필터링의 치트 방지 효과는 없다(온라인 모드에서만 유효).
- 스냅샷은 JSON이다. 인원이 크게 늘면 바이너리 인코딩과 델타 압축이 다음 단계다.
- 방은 모드당 1개(최대 8명)이고, 매치메이킹·계정·재접속 처리는 없다.
